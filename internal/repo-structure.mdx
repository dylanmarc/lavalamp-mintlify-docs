## Rules of thumb

<AccordionGroup>
  <Accordion title="One hook module per feature">
    `src/hooks/useChores.ts` owns every query and mutation that touches chores. Pages do not call `supabase` directly. If a page imports `supabase`, that is a smell worth fixing.
  </Accordion>
  <Accordion title="Query keys are centralised">
    Never inline a query key. `src/lib/queryKeys.ts` is the only place they are constructed, so invalidation always matches.
  </Accordion>
  <Accordion title="Types mirror the database">
    `src/types/index.ts` is hand-maintained against the schema. When you add a column, update the interface in the same commit as the migration.
  </Accordion>
  <Accordion title="Migrations are append-only">
    Never edit a migration that has been applied to staging or production. Write a new one. `db_schema.sql` is a dump for reference, not something to apply.
  </Accordion>
  <Accordion title="The legacy docs/ folder">
    `docs/` in the app repo predates this site. It is still accurate in places and stale in others (for example `TECHNICAL_DOCUMENTATION.md` still describes a single-flat model). Prefer this site; migrate anything useful you find and delete the original.
  </Accordion>
</AccordionGroup>
