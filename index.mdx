FlatApp is a Progressive Web App for shared households. A **flat** is the tenancy unit: every chore, expense, list, reminder and poll is scoped to one flat, and every user sees only the flats they are an active member of.

## The shape of the system in one paragraph

The client is a React 19 + TypeScript SPA built with Vite and served from Vercel. It talks directly to Supabase over the JS client: Postgres for storage, Row Level Security for authorisation, Realtime for live updates, and Auth for sessions. Anything that needs privilege the browser must not have (sending push, charging a card, deleting an account, rotating chores on a schedule) lives in a Supabase Edge Function or a `SECURITY DEFINER` Postgres function. Two scheduled jobs drive everything time-based: `chore-daily-job` once a day and `reminder-notifications` every fifteen minutes.

## Conventions used across these docs

| Term | Meaning |
| --- | --- |
| **Flat** | A household. The tenancy boundary for all data and all RLS policies. |
| **Member** | A row in `flat_members` with `status = 'active'`. A user can belong to several flats and has one `active_flat_id`. |
| **Queue then process** | The only sanctioned way to send a notification. Never call `send-push-notification` directly for user content. |
| **Optimistic mutation** | Every write goes through the helpers in `src/lib/optimisticMutations.ts` so the UI updates before the server confirms. |
